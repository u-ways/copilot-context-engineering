Apply this procedure when creating, or tightening, the path from a commit to production. `practices/continuous-integration.md` and `practices/actions-best-practices.md` cover the build side; `patterns/deployment.md`, `patterns/automate-everything.md`, `patterns/little-and-often.md` and `patterns/fast-feedback.md` set the shape of the flow; `patterns/enforce-code-formatting.md` and `practices/feature-toggling.md` describe the gates and switches that keep it safe. Check `blueprints.md` before building anything new, because a reusable starting point may already exist.
